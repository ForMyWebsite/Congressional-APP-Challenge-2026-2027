# Student usability session

Use synthetic data and explain the demonstration catalogue. Ask a participant to enter an engineering interest, prefer free participation, explain whether the record is real/open, save it, set a target, add homework, preview a schedule, approve it, reload, export, and delete. Observe without directing clicks. Ask what felt uncertain, whether the budget was understandable, and where they expected data to synchronize. Record consented observations without personal details. No testing results or educational outcomes have been collected.

# Congressional App Challenge demo outline

1. Relevance: describe unequal access to guidance without invented statistics.
2. Functionality: show optional profile → demonstration discovery → explained uncertainty → saved pathway → workload-aware preview → approval → reload.
3. Structure: explain App Router, shared Zod contracts, pure rules and browser persistence.
4. Code understanding: walk through match, toggleStep and schedule tests; explain dependency resets and conflict reporting.
5. UI: demonstrate keyboard focus, mobile navigation and uncertainty labels.
6. Impact: describe intended benefit as a hypothesis, then propose student usability research. Clearly disclose synthetic records, guest-only storage, deferred research and integrations. Do not claim a competition score.
